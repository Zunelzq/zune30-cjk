【教程】Zune 30 官方 3.3 固件原生显示中文（附步骤与资源）

一、一句话总结
第一代 Zune 30（30G）跑官方 3.3 (39)，现在能正常显示中文歌名、日文歌名和设备名，
英文界面保持原版 Zegoe 字体，Zune 软件同步正常。

二、先说清楚：这不是我一个人做到的
核心方法来自 GitHub 的 zune30-research 项目：镜像构建器、CE 工具链、注册表编辑器、
字体加载器都是他们的成果。我只做了三件事：
1）按他们的方案操作，发现并修正了三处会让它失败的配置错误；
2）把加载器写死的字体大小校验改成任意大小；
3）补上镜像打包、版本号修正、同步修复、降级回退，并写成脚本。

用之前请先给他们的仓库点 star：
https://github.com/1977899016-cell/zune30-research

本教程仓库（步骤更细、含脚本）：
https://github.com/Zunelzq/zune30-cjk

三、效果
· 开机画面：设备名中文正常显示（以前是方框）
· 音乐列表：中文歌名正常，例如「巨大少女」
· 日文歌名：「そらのおとしもの ～エターナル・イ...」正常
· 歌手名：「40mP, 初音ミク」正常
· 英文界面：仍是原版 Zegoe 字体，不是宋体
· 同步：Zune 4.8 可以正常同步歌曲

四、原理（一段话）
3.3 的界面通过系统 GDI 画字。GDI 支持 FontLink：
主字体（ROM 里的 Zegoe UI）缺哪个字形，就去第二个字体里找。
所以我们把中文字体注册成"回退字体"，并在界面启动前用一个极小的 ARM 程序
把它加载进 GDI。英文继续用 Zegoe，中文来自我们的字体。

三个前提，也是三个最大的坑：
1）必须换成 1.0 TEST 的启动器（零售 3.3 的启动器会校验 nk 签名）；
2）必须构建 AUTH196 镜像（3.3 在 1.0 时代的 vault 上会黑屏）；
3）字体必须放在 \Hard Disk —— 也就是 150MB 的系统分区，不是数据分区。

========== 第 3 楼（约 1300 字）==========
七、备份（最重要的一步，别跳）

把硬盘拆下来接适配器，以下文件必须原样备份到电脑：
· F:\ 整个分区（150MB 系统分区）
· G:\zunedb.dat      （约 4MB，3.3 的媒体库）
· G:\zunedb.BAK
· G:\drmStore.dat    （约 54MB，DRM 库）
· 再用备份助手导出 nor.original.bin、vault.legacy.bin、nk.original.bin

这三个 G 盘文件决定"刷完之后还能不能同步"。
如果只备份 F 盘而不备份它们，同步很可能永久坏掉。

八、大概步骤（1/2）

第 1 步：确认设备当前是 1.0 TEST 固件
· 开机画面有红色 TEST 字样、版本显示 1.0 (186) TEST
· 如果不是，需要先弄到 1.0 TEST 设备，或先按上游文档刷成 1.0 TEST

第 2 步：备份（见上一节）

第 3 步：安装 1.0 TEST 启动器
· 把 1.0 TEST 的 EBoot.bin 复制到 F:\EBoot.bin
· 同一包的 recovery.bin、zconfig.dat、pmcver.dat 也一并放入 F:\
· 装回设备开机一次，设备会把启动器刷进 NOR
· 开机画面应显示 Bootloader 2
注意：这一步不可逆。之后永远不能让 Zune 软件"修复/还原"设备，
也不要刷任何官方固件包，否则启动器被冲掉，自制镜像全部失效且无法恢复。

第 4 步：构建 3.3 兼容镜像（AUTH196）
· 用上游的 build_upgrade.py，输入：官方 3.3 的 nk.bin + 你自己的 vault
· 产出 nk.AUTH196.PRIVATE.bin
· 先单独把它写进 F:\nk.bin 并开机，确认能进 3.3 主界面，再继续

第 5 步：准备中文字体
· 用本仓库的 build_cjk_font.py 把字体子集化：
  去掉 hinting、改名为 Zune UI CJK、压成 GB2312 范围
· 实测：GB2312 全集约 8,011 字形，字体 1.9MB
· 放到设备：F:\Fonts\ZuneCJK_UI_20261027.ttf

第 6 步：修改字体加载器的尺寸校验
· 上游的 ZCJKBoot.exe 写死了字体必须正好 8,206,424 字节
· 用本仓库的 patch_loader.py 改成你字体的真实大小
· 放到设备：F:\Fonts\ZCJKBoot.exe

第 7 步：构建固件镜像
· 用本仓库的 build_image.py，它会做四件事：
  1）注册表加 FontLink（三个 Zegoe 面 → 你的字体）
  2）加开机启动项 Launch45 指向 ZCJKBoot.exe
  3）把固件版本号改成 03.30.00039.00-00435
  4）按原始结构重新打包 nk.bin
· 产出 nk.CJK.bin

========== 第 4 楼（约 700 字）==========
八、大概步骤（2/2）

第 8 步：写入设备
· 把 nk.CJK.bin 复制到 F:\nk.bin（覆盖）
· 建议用本仓库的 write_device.ps1，它会等待、重试、校验哈希

第 9 步：开机验收
· 能看到 3.3 主界面
· 英文仍是原版 Zegoe
· 设备名/歌名中文正常

第 10 步：如果同步坏了就修
· 现象：Zune 能识别设备但同步报 C00D11CD (80004005)
· 原因：刷机过程中失败启动会格式化系统分区，1.0 TEST 会重写数据分区媒体库
· 修复：把之前备份的 zunedb.dat、zunedb.BAK、drmStore.dat 放回 G:\
· 开机、连电脑、打开 Zune，同步即可恢复

九、最常见的坑

1）中文显示方框
按顺序查三项：
· 字体是不是真的在 F:\Fonts（不是 G:\Fonts）
· 字体内部家族名是不是和注册表里逗号后面的一字不差
· ZCJKBoot.exe 里的尺寸常量是不是等于字体文件的真实字节数

2）开机黑屏 / 反复重启
AUTH196 和这台设备的 vault 不匹配，回到第 4 步先验证基线

3）进系统后文字全部消失
字体太大或损坏，换 1-2MB 的小字体重试

4）英文变成了宋体
说明你走的是另一条"直接替换 ROM 字体"的路线，不是本文的 FontLink 方案

5）提示 please wait 然后要求连电脑
镜像被启动器拒绝，通常是 B000FF 记录结构被改动过，
用脚本重建，不要手工重排容器

6）同步报 C00D11CD
见第 10 步

========== 第 5 楼（约 810 字）==========
十、风险与边界
· 换启动器不可逆，请务必先备份，并保管好 F:\EBoot.bin
· 固件手术有风险，虽然启动器宽松（写错 nk 可以重写），但不保证零风险
· 目前只覆盖 GB2312 范围，生僻字仍会显示方框
· 菜单仍是英文（界面字符串在 strings.gem 里，本教程不涉及）
· 本仓库不分发任何微软固件、字体或设备专属文件
· 不要下载别人做好的"中文 nk.bin"——它内含对方设备的加密身份，
  你的机器用不了，作者也不该外发

十一、降级（3.3 退回 1.0 TEST）
只要启动器还是 1.0 TEST 的，把 1.0 TEST 的 nk.bin 写回 F:\ 就能退回去。
但降级前一定要备份 G:\ 的三个库文件，否则升回 3.3 后同步会坏。
详细流程：https://github.com/Zunelzq/zune30-cjk/blob/main/docs/11-downgrade.md
