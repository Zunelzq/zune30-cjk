## 正文

---

先说结论：**一台第一代 Zune 30（30GB），跑的是官方 3.3 (39) 固件，现在可以原生显示中文和日文。**

- 设备名：中文正常显示，不再是方框
- 中文歌名：`巨大少女`
- 日文歌名：`そらのおとしもの ～エターナル・イ...`
- 歌手：`40mP, 初音ミク`

### 为什么以前大家都说不行

十几年来公认的说法是：Zune 30 只有 **1.0 TEST / 1.4** 能显示中文（因为那两版走 GDI 的
FontLink），3.3 不行。连专门做 Zune 30 研究的 `zune30-research` 项目，README 里也写明
"3.3 兼容镜像不含中文"。

### 真正的原因（这次实测确认）

3.3 的界面程序 `gemstone.exe` **根本不走 GDI 的字体回退**。它的 UI 字体是自己从 ROM 里读的：

```
\Windows\ZegoeUI.ttf       （常规）
\Windows\ZegoeUI_L.ttf     （细体）
\Windows\ZegoeUI_SB.ttf    （半粗，默认）
```

所以：

- 加注册表 `FontLink` → 无效
- 改 `Software\Microsoft\Zune\Fonts\*` 的 Locator → 无效
- 加 `FallbackFont` → 无效
- 写个开机加载字体的 ARM 程序 → 无效
- 把两个 ROM 字体在注册表里互换 → **界面毫无变化**（这一步证明了注册表根本没被读）

而把这**三个 ROM 文件的内容**换掉，界面字体立刻变。这就是突破口。

### 难在哪：ROM 空间

镜像只剩 36 KB 空闲，一个能用的中文字体压缩后要 160–180 KB。

解决办法：

1. **原地压缩 `skin_default.gem`**（464 KB → 334 KB），CE 的 ROM 文件系统会对
   `flags |= 0x800` 的文件透明解压，所以压缩后照样能读；
2. 腾出来的尾部空间和后面的 **FM 收音机固件槽位**（`Acs_*.hex`，实际不用）
   以及两个 **ZDK 示例场景包**槽位连成 163–180 KB 连续空间；
3. 把"去掉 hinting 的中文 TTF 子集"用 **CE-LZX（块必须 4096 字节）** 压缩后放进去，
   三个 Zegoe 条目全部指向它。

### 前提：一个不验签的启动器

零售 3.3 的 EBoot 会校验 `nk.bin`。突破口是 **1.0 TEST 的启动器**：它被生产熔丝接受，
但**不校验 nk**。它一旦进了 NOR，之后任何自制镜像都能启动。

### 文档里还写了什么

- 不拆芯片读出 NOR / vault 的方法（利用测试固件开机执行 `qtk.exe` 的机制）；
- 用官方 3.3 + 自己的 vault 构建 AUTH196（让 3.3 在旧 vault 上跑起来）；
- 刷机后 Zune 报 `C00D11CD` 的修复方法（恢复自己的 `zunedb.dat` / `drmStore.dat`）；
- 修正固件版本串让 Zune 客户端不再认为"需要升级"；
- **一份很长的失败清单**：搬移 `.gem` 会黑屏、重排 B000FF 记录会启动失败、
  追加乱序记录会被拒、MTP 直传媒体会被设备重置……这些坑都写在里面。

### 仓库

https://github.com/Zunelzq/zune30-cjk

只放**文档和脚本**（MIT），不含微软固件、不含字体、不含任何设备专属文件。
固件和字体都用你自己手上的。

### 必须说明的局限

- ROM 空间只塞得下 **1,050 个汉字**，生僻字仍会方框；
- 英文字形换成了中文字体自带的拉丁字形（偏宋体）；
- FM 收音机固件槽位被占用，所以收音机固件更新用不了（Zune 的 FM/Wi-Fi 服务本身也早停了）。
