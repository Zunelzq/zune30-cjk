# 04 — AUTH196: booting official 3.3 on a 1.0-era vault

## The problem

A 1.0 TEST device has an old-format **vault** in NOR (offset `0x70000`, 64 KiB). Official
3.3 expects the new format. Load a stock 3.3 `nk.bin` under the TEST loader and you get:
splash → black screen → reboot. The kernel starts, then the crypto layer fails.

## The solution (public tooling)

`zune30-research`'s `build_upgrade.py` produces **AUTH196**: an official 3.3 image with a
small ARM routine appended that, at boot, reads the embedded copy of your legacy vault and
re-wraps it into the format 3.3 expects — **in RAM only**.

```powershell
python tools\upgrade\build_upgrade.py `
  --stock-nk      official-3.3-nk.bin `
  --legacy-vault  vault.legacy.bin `
  --vault-sha256  <sha256> `
  --decompressor-dir app\vendor `
  --output-dir    out\auth196
```

The builder refuses to run unless the stock image hash is the pinned official 3.3
(`81951eaf10feb868…`), which protects you from reusing offsets on the wrong image.

Report fields worth checking:

```
image_bytes           13,956,899
runtime_bytes          1,700      (the vault re-wrap routine)
rom_legacy_file_roundtrip_verified   true
runtime_module_overlap               false
```

## What it changes in the ROM (all inside the official image)

| Change | Purpose |
|---|---|
| appends a 0x3000 code cave to `ceddk.dll` | the runtime routine |
| patches the `keyvault.dll` call site | jumps into the cave |
| stubs the security-write handler | keeps writes in RAM |
| stores the packed vault as a new ROM file `ZV194.dat` | source data |
| sets `ceconfig.h`'s slot to `ZV194.dat` | reuses an unused file table entry |

## Limitations that matter later

* The re-wrap is **RAM only** — the device cannot persist security state
  (`persistent_security_write_implemented: false`). This does not prevent booting, playing
  music or syncing once the original media/DRM stores are restored, but it is why the
  device reports an odd firmware string and why "repair" must never be used.
* The generated image **contains your encrypted vault**. Treat it as private; never commit
  it, never share it, never upload it.

## Sanity test before you customise anything

1. write `nk.AUTH196.bin` to `F:\nk.bin` (TEST bootloader already in NOR);
2. boot: 3.3 UI, `Version 3.30 (39)`, `Bootloader 2`;
3. if you get a black screen, the vault does not match this device — do not continue.

Only after this baseline works should you start with fonts (`05`, `06`).
